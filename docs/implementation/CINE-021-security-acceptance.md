## Limits and operation

- Per 60-second window, the network quotas are 20 create, 30 join, 60 vote and 24 token requests. Signed guests have 60 vote and 12 token requests per room. Both create paths share a quota, as do both join paths and the vote aliases. A denied request returns `429`, `Retry-After`, and `no-store`.
- Vercel supplies the network identity at ingress. IPv6 accounts for a /64. Requests without a trusted address share a network bucket. SQLite uses an in-process counter for offline development and tests. PostgreSQL is required for the shared production authority. Expired counters stop enforcing the old window immediately and are pruned in bounded batches as traffic continues.
- Supabase session-mode endpoints on port 5432 default to two connections per application pool. `CINEMATCH_PG_POOL_MAX` accepts 1–10, and the outbox worker uses at most two. The hosted 15-session limit applies to the combined deployment. Budget all app processes, live route pools, the worker, and administrative sessions before release. Pooler capacity rejection returns `503` with `Retry-After: 3`; quota rejection remains `429`.
- Browser wake events can accelerate local reconnect backoff. They cannot shorten a server `Retry-After` pause on token or snapshot requests. Healthy 60-second room tokens still rotate at about 30 seconds.
- Apply migration 006 before starting the new app and outbox worker. Keep `cinematch_private` outside exposed API schemas. Self-hosted deployments terminating TLS at a proxy use `CINEMATCH_APP_ORIGIN` for the public browser origin. If rolling back 006, revert the application and worker binaries first. The down migration has been designed to preserve room data and restores the pre-006 policy definitions.
- Alert on `CINEMATCH_REALTIME_AUTH` and verify that the configured server key matches the project and broadcast permissions. Check provider connectivity and the age of the oldest eligible outbox event on `CINEMATCH_REALTIME_UNAVAILABLE`. Inspect quarantined event counts on `CINEMATCH_REALTIME_REJECTED`. Transient retries are capped at 60 seconds between attempts. Authorization retries wait at least 60 seconds and at most 15 minutes between attempts. A rejected oversized event is quarantined after three permanent failures. Outbox hints remain best-effort and room snapshots remain authoritative.
- CINE-018 recorded a partial credential fragment in a private tool trace. Published scans and the owner's report about access to the trace do not establish who could access private records. Review trace access with the owner or provider if the scope changes. A fragment with no verified outside access does not justify rotation by itself. Do not include live keys, cookie values, JWTs or raw transport traces in evidence.
- Real hosted JWT signature, expiry, subscription, and reconnect behavior require the managed Realtime service after migration. Local SQL role checks isolate the policy decision. CINE-019 owns client reconnect and concurrency behavior.

## Active adversarial and capacity qualification (takeover, 2026-11-19)

All three suites run only against the dedicated loopback container labelled `cinematch.task=CINE-021` (`127.0.0.1:55440`) with disposable databases and synthetic fixtures; they never contact hosted services. Start it with the pinned `supabase/postgres` image, then:

```text
npm run build
CINE021_ADV_PGPASSWORD=<container password> node tests/local-supabase/cine021-adversarial-qualification.cjs
CINE021_ADV_PGPASSWORD=<container password> npx tsx --conditions=react-server tests/local-supabase/cine021-publisher-fault-qualification.ts
CINE021_ADV_PGPASSWORD=<container password> node tests/local-supabase/cine021-capacity-qualification.cjs --apps=1,6,8
```

- **Adversarial (production `next start`; non-VERCEL ingress and VERCEL ingress with a configured `CINEMATCH_APP_ORIGIN`; the Host-derived origin branch without it was probed independently by the reviewer, not by this suite):** brute-force join, concurrent mass create (exactly 20 admitted of 150), forged/expired/tampered/rotated capabilities, cross-room IDOR over HTTP and over PostgreSQL roles, CSRF matrix, XSS payloads, oversized/chunked/malformed bodies, log and error-body secret scan, quota-table opacity.
- **Publisher faults (real HTTP provider stub, real outbox):** URL allow-list, redirects never followed, 401/403 cooldown, 413 quarantine, 5xx/reset/hang backoff and ordering, hint-only payload, pool starvation bound.
- **Capacity (role `CONNECTION LIMIT 15` emulating the session-pooler budget; real app processes with `CINEMATCH_PG_POOL_MAX=2` plus the real worker):** 1 app + worker peaks at 3 connections, 6 apps + worker at 13 with no capacity errors, 8 apps + worker reaches 15 and sheds load as sanitized `503` + `Retry-After: 3` with no orphan rooms, host mismatches or leaked detail, and every process recovers when load stops. This emulates the session budget only; it is not Supavisor, and a transaction-mode pooler was not available locally. The room code uses only transaction-scoped locks and `SET LOCAL`, but that compatibility is unverified against a real transaction pooler.
- **Sizing rule:** the combined budget is (app processes x pool max, default 2) + 2 (worker) + administrative sessions <= 15. Beyond roughly six concurrent app processes, session-mode hosting degrades to `503` rather than failing unsafely. A horizontally scaling serverless deployment should move to a transaction-mode pooler (after verifying it) or a higher session limit before launch; this is a release gate for CINE-028, not a defect fixed by CINE-021.
- **Known residual:** `filters`, `start`, `leave`, `rotate` and `host-check` have CSRF and capability checks but no per-guest quota. A room member can spend their own room's database work; the measured effect on another room under 16+16 concurrent spammers was none beyond sub-second latency.
- **Non-Vercel hosts:** all unauthenticated create/join traffic shares one network bucket, so a single client can exhaust it (30 requests a minute) and lock everyone out. Do not launch on a non-Vercel host without a trusted client-address source or an upstream limiter.
- **Other unthrottled work:** authenticated GET routes (snapshot, deck, events, session) call the post-commit notifier, which costs a transaction. The app pool has no statement or idle timeout (the worker does): a flood that passes CSRF/ingress checks can queue on the 2-connection pool for up to 10 s and be shed as `503`. Platform firewall/WAF limits are the intended coarse control and are not verified here.
- **Publisher cooldown scope:** the 5 s cooldown is per process and starts on any non-2xx, non-401/403/413 provider response, so one room's provider-side error pauses sends for all rooms in that process for 5 s per probe. Events stay pending and the worker retries.
